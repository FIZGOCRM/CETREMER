# GoMut KVM4 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. The user's deploy prompt is the approved specification and execution authorization.

**Goal:** Run the current GoMut release, including uncommitted D01–D04, on the actual KVM4 and validate it through SSH tunnels.

**Architecture:** Dedicated Docker Compose project on the existing engine, without joining or changing other projects. Gunicorn and WhiteNoise; loopback-only publication for production and a separately identified homologation database. Local image build avoids competing with the VPS workload. The existing Coolify/Traefik remain unchanged; this tunnel phase does not register a public route or create DNS.

**Tech Stack:** Python 3.13, Django 5.2.19 LTS, Gunicorn, WhiteNoise, SQLite on ext4 bind mounts.

**Spec:** `docs/PROMPT-DEPLOY-KVM4-CODEX-DESKTOP.md`, plus the user's current SSH key authorization.

## Global Constraints

- Preserve all existing services, keys and authentication methods.
- Include current working tree D01–D04, not just HEAD.
- No local database, uploads, secrets, seed.py or environment transferred.
- New production database, separate homologation; no real learner data fabricated.
- Domain/DNS, Hostinger billing and global firewall outside scope.
- Stop new deployment work if it degrades existing services.

## Review Focus

- A Docker restart must preserve SQLite and uploaded material.
- Direct PDFs and path traversal must not expose private files.
- Tunnel-only HTTP settings must reject wildcard hosts and untrusted forwarding headers.
- Scheduler and backups must not overlap, or claim SMTP delivery without configuration.
- Resource checks must compare original container identities, restart counts and health.
