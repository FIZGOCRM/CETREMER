# CETREMER: segurança e separação de responsabilidades

**Objetivo:** tratar os pontos de atenção do artefato mantendo Django, templates e SQLite.

**Arquitetura:** views adaptam HTTP; forms validam entradas; selectors consultam; services executam casos de uso; integrations isolam HTTP externo. O ORM continua sendo a persistência, sem repositórios genéricos ou uma alegação de Clean Architecture estrita.

**Restrições:** sem React/Vue, FastAPI/DRF ou PostgreSQL. Sem gateway escolhido, não simular recebimentos nem implementar confirmação pública. Preservar cadastro/matrícula manual e recuperação de conta. Não apagar dados ou configurações históricas sem migração específica.

## Execução e critérios

- [x] Checkout: regressões para visitante, aluno e produtor; nenhum usuário, pedido ou matrícula criado sem gateway. Remover coleta fictícia de cartão e mensagem falsa de sucesso.
- [x] Cursos: selectors de progresso e services de conclusão/emissão. Regras independentes de request/response; progresso e pontos consistentes; emissão idempotente e transacional.
- [x] Certificados: GET consulta requisitos ou certificado existente; POST emite e redireciona; atualizar testes e interface.
- [x] Validação: Forms para edição de curso/aula e matrícula manual; entradas inválidas não persistem. Vimeo em integração com timeout e captura específica de erros.
- [x] Organização: dividir painel em módulos, remover views antigas sem referências; preservar URLs e permissões. Extrair importação de alunos para módulo de parsing e serviço transacional.
- [x] Operação: ferramenta de backup consistente via API SQLite, instruções de restauração e teste real de integridade do backup.
- [x] Evidências: executar suite completa, system check e verificação de migrations; atualizar artefato para distinguir o corrigido das dependências externas.
